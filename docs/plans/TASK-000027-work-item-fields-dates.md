# TASK-000027: Custom fields, плановые даты и расширенная фильтрация — PLAN

Статус: completed

База: `main` (`6020306`, merge TASK-000029). Alembic head — `c8a51d70b394`,
единственный; новая ревизия ставится поверх, ветвления не возникает.

## Порядок и его причина

Снизу вверх: домен без БД → схема → команды → чтение → поверхности → документы.
Обратный порядок («сначала параметры эндпоинта») дал бы промежуточные коммиты,
где фильтр по дате уже принимается, а колонки ещё нет.

Отдельно: сортировка по дате делается **после** фильтров, а не вместе с ними.
Фильтр — это предикат, сортировка — это второй формат курсора; смешав их в одном
шаге, легко получить курсор, который «почти работает» под чужим порядком.

## Вертикальные TDD slices

### S1. Домен

RED (`tests/unit/test_work_item_domain.py`): custom fields по схеме типа
принимаются; нарушение `required` / типа / `enum` / `additionalProperties` —
`custom_fields_invalid`; пустая схема принимает всё; секрет — отказ, `secretRef`
— нет; внешний `$ref` в сохранённой схеме — `invalid_json_schema` без сетевого
обращения; документ сверх лимита — `payload_too_large`; naive дата читается как
UTC; обратный интервал — `invalid_planned_dates`.

GREEN: `validate_task_custom_fields`, `normalize_planned_date`,
`validate_planned_dates` в `domain/work_item.py` — поверх уже существующих
`validate_against_schema` и `reject_secret_material`, без второго механизма.

### S2. Схема и миграция

Ревизия `a1c7e94b2f60`: три колонки, CHECK на порядок дат, три индекса (два
частичных). Тест — `test_fields_revision_is_additive_and_reversible`, плюс
обновлённые константы head в тестах миграций v0.5/v0.7.

### S3. Команды

`create_task` валидирует поля против типа, который сам же и резолвил;
`update_task` — против типа, закреплённого задачей, и сверяет одну переданную
дату с сохранённой второй. Отказ происходит до мутации, поэтому версия не
двигается. В журнал уходит факт изменения полей, не содержимое.

### S4. Чтение

Фильтры `ownerId` и четыре границы дат; `_paginate_by_date` с курсором
собственного формата. Тесты покрывают: включающие границы, исключение задач без
даты, NULL-хвост, полный обход страницами по 2 при трёх равных датах, фильтр до
курсора, чужой курсор → `invalid_cursor`, неизвестный `sort` → `invalid_sort`,
изоляция тенанта.

### S5. Поверхности

Клиент и MCP. Очистка даты в MCP — флагами, потому что там `None` значит «не
трогать»; установка и очистка одной даты одновременно отклоняются.

### S6. Документы

ADR-0049 + реестр ADR, `docs/api.md`, `docs/migration-v0.8.md`,
`docs/architecture.md`, `docs/claude-code.md`, SPEC/PLAN/verification.

## Что сознательно не делалось

- `web/` не трогали: поля и даты не отображаются в интерфейсе — это отдельная
  работа, у которой свои критерии приёмки;
- фильтр по значению внутри `custom_fields` — требует индексируемой схемы
  запроса, отдельное решение;
- обратной совместимости ради `sort` по умолчанию остался `createdAt`.
