# TASK-000026: Обобщение external references — threat/failure model

Статус: completed

Связанные документы: `docs/specs/TASK-000026-external-references.md`,
`docs/plans/TASK-000026-external-references.md`,
`docs/adr/0047-generic-external-references.md`.

## 1. Активы

| Актив | Почему ценен |
|---|---|
| Пространство внешних ключей тенанта | `(system, type, externalId)` уникален глобально в тенанте: занятый ключ нельзя переиспользовать |
| Отображение внешний ключ → внутренняя сущность | раскрывает, какие чужие тикеты/карточки заведены в тенанте и чем они являются |
| `metadata` ссылки | свободный документ от клиента — типичное место для токенов и внутренних URL |
| Право записи на сущность | регистрация ссылки — мутация, привязанная к задаче или проекту |
| Поток событий | доставляется шире, чем сама строка |

## 2. Модель нарушителя

- **A1. Импортёр с узким ключом** (`tasks.read`, `tasks.write`): легитимно
  переносит операционный слой; риск — получить через ссылки больше, чем задачи.
- **A2. Принципал другого тенанта**: хочет увидеть или занять чужое
  отображение.
- **A3. Внешний наблюдатель с любым валидным ключом**: перебирает внешние
  идентификаторы, чтобы узнать, что заведено в тенанте.
- **A4. Prompt injection в задаче**: заставляет агента зарегистрировать ссылку
  на сущность, к которой у него нет права.
- **A5. Подписчик событий**: видит поток, но не обязан видеть содержимое
  `metadata`.

## 3. Угрозы и контроли

| # | Угроза | Вектор | Контроль | Проверка |
|---|---|---|---|---|
| T1 | Обход авторизации через свободный `entityType` | A1/A4 объявляет тип, для которого проверки нет | реестр bindings: неизвестный тип → `422 invalid_entity_type` **до** любой записи | `test_unknown_entity_type_is_rejected_before_any_write` |
| T2 | Эскалация с задач на проекты (и обратно) | A1 указывает `entityType=project` | право берётся из binding целевого типа, а не из проекта | `test_permission_follows_the_entity_type_not_the_project` |
| T3 | Захват внешнего ключа (отказ в обслуживании импорта) | A1 занимает ключ на несуществующую сущность | сущность резолвится до записи; несуществующая → `404` | `test_reference_to_a_missing_entity_is_rejected` |
| T4 | Кросс-тенантная привязка | A2 подставляет UUID чужой задачи | загрузчик фильтрует по `tenant_id`; чужое неотличимо от отсутствующего (`404`) | `test_reference_does_not_cross_the_tenant_boundary` |
| T5 | Enumeration внешних идентификаторов | A3 перебирает `?externalSystem=&externalId=` | выдача фильтруется правом чтения найденного типа; недоступное **отсутствует**, а не даёт `403` | `test_reverse_lookup_hides_types_the_caller_cannot_read` |
| T6 | Подмена цели существующего ключа | A1 перерегистрирует ключ на свою сущность | сравнение пары `(entity_type, entity_id)`; расхождение → `409` | `test_external_key_is_exclusive_across_entity_types` |
| T7 | Утечка секрета через `metadata` | токен в документе | `guard_json_document` (границы) → `validate_config_document` (рекурсивный scan), отказ записи | `test_secret_material_in_metadata_is_refused` |
| T8 | Утечка `metadata` в поток событий | A5 читает события | payload события не содержит `metadata` | код `_record`; `docs/api.md`, раздел событий |
| T9 | Молчаливая выдача «всего» при полузаданном фильтре | A3 отправляет только `externalId` | `validate_lookup_arguments` → `422 invalid_external_lookup` | `test_ambiguous_lookup_is_refused` |
| T10 | Подмена идентичности записи после создания | прямой UPDATE в БД | триггер `forbid_external_reference_identity_change` | `test_external_reference_identity_is_unique_and_immutable` (существующий) |

## 4. Failure model

| Сценарий | Поведение |
|---|---|
| Гонка двух создателей одного ключа | уникальный индекс внутри `SAVEPOINT`: один `201`, второй `409`, транзакция жива |
| Повтор того же тела | `200`, строка не пишется, `version` не растёт, события нет |
| Тот же ключ, другое `metadata` | `200`, меняется только `metadata`, `version += 1`, событие `updated` |
| Пагинация под конкурентными вставками | курсор по `(created_at, id)` — тот же порядок, что у остальных списков |
| Ключ без права чтения ни одного типа | пустая страница, запрос до БД не доходит |
| Ссылка длиннее границы | `422 invalid_entity_reference` / `invalid_external_reference` |

## 5. Осознанно не закрыто

- **Удаление ссылки через API отсутствует** (ограничение ADR-0034). Ошибочная
  привязка исправляется только на уровне БД. Расширять поверхность записи в
  рамках этой задачи не стали: удаление отображения — отдельное решение с
  собственным audit-следом.
- **Факт существования ключа виден владельцу типа.** Принципал с `tasks.read`
  видит все task-отображения тенанта. Это соответствует текущей модели прав
  (task-скоуп не сегментирован по workspace для чтения) и не вводится этой
  задачей.
- **Тайминг обратного поиска** не выравнивается: путь «нет ключа» и путь «ключ
  есть, но тип не читается» различаются одним предикатом SQL. Считаем
  приемлемым — оба идут через один запрос без ветвления в приложении.
